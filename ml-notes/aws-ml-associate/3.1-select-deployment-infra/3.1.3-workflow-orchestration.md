# ML Workflow Orchestration

Orchestration is the process of coordinating and managing the steps involved in building, training, and deploying machine learning (ML) models. AWS provides several services to streamline and automate this process.

## Workflow Orchestration Options on AWS

AWS offers several solutions for production ML workflows:

-   **Amazon SageMaker Pipelines**: A purpose-built, end-to-end ML workflow service.
-   **AWS Step Functions**: A serverless way to orchestrate pipelines, including ML-based ones.
-   **Amazon Managed Workflows for Apache Airflow (Amazon MWAA)**: Uses Python-based Directed Acyclic Graphs (DAGs) to orchestrate workflows.
-   **Third-Party Tools**: Includes tools like MLflow and Kubernetes.

---

## Amazon SageMaker Pipelines

SageMaker Pipelines is a purpose-built solution for creating, reusing, and sharing ML workflows at scale. It integrates directly with SageMaker features and other AWS services.

### Model Building Pipeline with SageMaker

![Model Building Pipeline with SageMaker](../assets/3.1.3_modelBuildingPipeline.png)

A typical model building pipeline involves several integrated services:

1.  **Data Source Integration**: Configure permissions to access your data sources.
2.  **SageMaker Feature Store**: Store, manage, and reuse features for training jobs.
3.  **SageMaker Processing**: Preprocess data and create training, testing, and validation sets using tools like Data Wrangler and Clarify.
4.  **Amazon ECR**: Store and pull training container images.
5.  **SageMaker Training**: Run the training job using the processed data and container image.
6.  **Model Validation**: Test the trained model against performance requirements.
7.  **SageMaker Model Registry**: Register models that meet performance requirements, recording the model artifact and inference container location.

### SageMaker Pipeline Step Types

![SageMaker Pipeline Step Types](/assets/3.1.3_sagemakerPipelineStepTypes.png)

Pipelines are constructed from steps, including:

-   **Processing**: For data processing and model evaluation.
-   **Training**: For model training using SageMaker Training Jobs.
-   **Conditional**: To evaluate a condition and branch accordingly.
-   **CreateModel**: To package the model for deployment.
-   **RegisterModel**: To create a model package in the registry.
-   **Fail**: To stop and mark a pipeline's execution as failed.

## Other Orchestration Services

### AWS Step Functions

![AWS Step Functions](/assets/StateWorkflowv2.png)

Step Functions orchestrates workflows for model training, evaluation, and deployment using a serverless, event-driven approach. Workflows are defined as state machines (a type of DAG) in the Amazon States Language.

### Apache Airflow and Amazon MWAA

Apache Airflow is a platform to programmatically author, schedule, and monitor workflows. With Amazon MWAA, you can manage Airflow in AWS.

-   **Python-based**: Define workflows programmatically in Python.
-   **DAG Workflow Management**: Define and visualize complex workflows with dependencies.
-   **Extensibility**: Use operators to perform common tasks and orchestrate long-running processes.

### MLflow

MLflow is an open-source platform to manage the end-to-end ML lifecycle.

-   **Tracking**: Record and query experiments (code, data, config, results).
-   **Projects**: Package code for reproducible runs.
-   **Models**: Deploy models in diverse environments.
-   **Registry**: Store, annotate, and manage models in a central repository.

### Kubernetes

Kubernetes can be used to orchestrate ML workflows on AWS, allowing you to train, tune, and deploy models in SageMaker directly from a Kubernetes environment.

-   **AWS Controllers for Kubernetes (ACK)**: Use SageMaker Operators to create SageMaker jobs with the Kubernetes API (e.g., `kubectl`) on an Amazon EKS cluster.
-   **SageMaker Components for Kubeflow Pipelines**: Move data processing and training jobs from a Kubernetes cluster to SageMaker's managed service, integrating SageMaker resources into a Kubeflow Pipelines workflow.
