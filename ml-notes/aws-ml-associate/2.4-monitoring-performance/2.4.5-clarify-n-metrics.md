# Amazon SageMaker Clarify: Bias Detection and Model Explainability

## 1. Overview and Purpose

**Amazon SageMaker Clarify** is a comprehensive tool within SageMaker designed to improve the fairness, transparency, and explainability of machine learning models. It provides capabilities for bias detection, model explainability, and data quality monitoring throughout the ML lifecycle—from data preparation to production deployment.

### Core Concepts:

- **Explainability:** The ability to interpret how a machine learning model uses input features to make predictions in human-understandable terms. Explainability is critical for building trust, debugging models, and meeting regulatory requirements.

- **Fairness:** Ensuring that ML models do not systematically disadvantage specific groups based on sensitive attributes (e.g., age, gender, race, ethnicity). Fairness evaluation helps design inclusive systems that minimize bias.

- **Bias:** Systematic errors in model predictions that favor or disadvantage certain groups. Bias can arise from imbalanced training data, feature selection, or model architecture.

### Why It Matters:
Biased or opaque models can lead to unfair outcomes, regulatory violations, and loss of user trust. SageMaker Clarify enables practitioners to proactively detect and mitigate these issues before deployment.

## 2. Key Capabilities Throughout the ML Lifecycle

### 2.1 Pre-Training: Bias Detection in Data
**Purpose:** Identify bias in training data before model training begins.

**Capabilities:**
- Detects imbalances in sensitive attributes (facets) such as age, gender, or race.
- Provides nine pre-training bias metrics (e.g., Class Imbalance, Facet Imbalance).
- Helps ensure representative and balanced training datasets.

**Use Case:** Before training a credit risk model, detect if certain demographic groups are underrepresented in the dataset.

### 2.2 Post-Training: Bias Detection in Models
**Purpose:** Evaluate bias in trained model predictions.

**Capabilities:**
- Provides nine post-training bias metrics (e.g., Differential Prediction Bias, Differential Validity).
- Compares model performance across different facet groups.
- Identifies disparate impact and treatment.

**Use Case:** After training a hiring recommendation model, verify that it does not favor candidates from specific demographic groups.

### 2.3 Model Explainability: Global and Local Predictions
**Purpose:** Understand how models make predictions.

**Capabilities:**
- **Global Explainability:** Identifies the most important features for overall model behavior.
- **Local Explainability:** Explains individual predictions by quantifying feature contributions.
- Supports SHAP (SHapley Additive exPlanations) for feature attribution.

**Use Case:** Explain why a loan application was rejected by showing which features (e.g., income, credit score) contributed most to the decision.

### 2.4 Computer Vision and NLP Explainability
**Purpose:** Provide transparency for unstructured data models (images, text).

**Capabilities:**
- Visualizes which regions of an image influenced a prediction (e.g., heatmaps for object detection).
- Highlights important words or phrases in text classification tasks.

**Use Case:** In a medical imaging model, highlight the regions of an X-ray that led to a diagnosis of pneumonia.

### 2.5 Drift Detection and Monitoring
**Purpose:** Detect changes in data distributions and model behavior over time.

**Capabilities:**
- Integrates with SageMaker Model Monitor to detect data drift and bias drift.
- Alerts when production data deviates from training data distributions.
- Monitors for concept drift (changes in the relationship between features and target).

**Use Case:** Detect if a fraud detection model's performance degrades due to shifts in transaction patterns.

### 2.6 Automated Reporting
**Purpose:** Generate comprehensive bias and explainability reports.

**Capabilities:**
- Visual reports with bias metrics, severity assessments, and recommendations.
- Exportable reports for regulatory compliance and stakeholder communication.

**Use Case:** Generate a fairness audit report for a lending model to demonstrate compliance with fair lending regulations.

## 3. SageMaker Clarify Metrics: Four Categories

### 3.1 Data Bias Metrics (Pre-Training)

These metrics evaluate bias in training data before model training.

- **Class Imbalance (CI):**
    - **Definition:** Measures imbalance in the distribution of class labels.
    - **Formula:** `CI = (n_majority - n_minority) / n_total`
    - **Interpretation:** Values close to 0 indicate balanced classes; values close to 1 indicate severe imbalance.
    - **Use Case:** Detect if a fraud detection dataset has far fewer fraud cases than legitimate transactions.

- **Facet Imbalance (FI):**
    - **Definition:** Evaluates imbalance in sensitive attributes (facets) across classes.
    - **Formula:** Compares the proportion of a facet value in one class vs. another.
    - **Interpretation:** Values significantly different from 1 indicate imbalance.
    - **Use Case:** Check if male applicants are overrepresented in the "approved" class of a loan dataset.

- **Facet Correlation:**
    - **Definition:** Measures correlation between sensitive attributes and the target variable.
    - **Interpretation:** High correlation may indicate that the model could learn biased patterns.
    - **Use Case:** Identify if age is highly correlated with loan approval, which could lead to age-based discrimination.

### 3.2 Model Bias Metrics (Post-Training)

These metrics evaluate bias in trained model predictions.

- **Differential Validity (DV):**
    - **Definition:** Measures differences in model performance (accuracy, precision, recall) across facet groups.
    - **Formula:** `DV = Metric_GroupA - Metric_GroupB`
    - **Interpretation:** Values close to 0 indicate similar performance; large values indicate disparate performance.
    - **Use Case:** Verify that a hiring model has similar accuracy for male and female candidates.

- **Differential Prediction Bias (DPB):**
    - **Definition:** Measures differences in predicted outcomes for different facet groups with the same input features.
    - **Interpretation:** Non-zero values indicate the model treats groups differently.
    - **Use Case:** Check if a credit scoring model assigns different scores to applicants with identical financial profiles but different genders.

- **Differential Feature Importance (DFI):**
    - **Definition:** Analyzes differences in feature importance across facet groups.
    - **Interpretation:** Large differences suggest the model relies on different features for different groups.
    - **Use Case:** Identify if a medical diagnosis model uses different symptoms to diagnose men vs. women.

### 3.3 Model Explainability Metrics

These metrics provide transparency into model decision-making.

- **SHAP (SHapley Additive exPlanations):**
    - **Definition:** Quantifies the contribution of each feature to a specific prediction using game theory.
    - **Interpretation:** SHAP values indicate how much each feature increases or decreases the prediction.
    - **Use Case:** Explain why a loan was denied by showing that low income (-0.3) and high debt-to-income ratio (-0.2) were the main negative contributors.

- **Feature Attribution:**
    - **Definition:** Identifies the most important features for a specific prediction.
    - **Interpretation:** Features with high attribution scores have the most influence.
    - **Use Case:** In a product recommendation model, show that "purchase history" and "browsing behavior" are the top contributors.

- **Partial Dependence Plots (PDPs):**
    - **Definition:** Visualizes the marginal effect of one or more features on model predictions.
    - **Interpretation:** Shows how predictions change as a feature varies, holding others constant.
    - **Use Case:** Visualize how increasing credit score from 600 to 800 affects loan approval probability.

### 3.4 Data Quality Metrics

These metrics assess the quality and integrity of training and production data.

- **Missing Data:**
    - **Definition:** Identifies the presence and distribution of missing values.
    - **Interpretation:** High percentages of missing data can degrade model performance.
    - **Use Case:** Detect if 30% of income values are missing in a loan application dataset.

- **Duplicate Data:**
    - **Definition:** Detects duplicate instances or rows.
    - **Interpretation:** Duplicates can bias the model toward overrepresented patterns.
    - **Use Case:** Identify if the same transaction appears multiple times in a fraud detection dataset.

- **Data Drift:**
    - **Definition:** Measures statistical differences between training and production data distributions.
    - **Interpretation:** Significant drift indicates the model may not generalize well to production data.
    - **Use Case:** Detect if the distribution of transaction amounts in production has shifted compared to training data.

## 4. Comprehensive Example: Loan Approval Model

### Scenario: Building a Fair Loan Approval System

A financial institution is building a machine learning model to automate loan approval decisions. The model predicts whether to approve or deny loan applications based on features such as income, credit score, employment history, and debt-to-income ratio. The institution wants to ensure the model is fair, transparent, and compliant with fair lending regulations.

---

### Step 1: Pre-Training Bias Detection

**Objective:** Analyze training data for bias before model training.

**Dataset:**
- 10,000 loan applications
- Features: Income, Credit Score, Employment History, Debt-to-Income Ratio, Age, Gender
- Target: Approved (1) or Denied (0)

**SageMaker Clarify Analysis:**

```python
from sagemaker.clarify import DataConfig, BiasConfig, ModelConfig
from sagemaker import clarify

# Configure data
data_config = DataConfig(
    s3_data_input_path='s3://bucket/loan_data.csv',
    s3_output_path='s3://bucket/clarify_output',
    label='approved',
    headers=['income', 'credit_score', 'employment', 'dti', 'age', 'gender'],
    dataset_type='text/csv'
)

# Configure bias detection for gender facet
bias_config = BiasConfig(
    label_values_or_threshold=[1],
    facet_name='gender',
    facet_values_or_threshold=[0]  # 0 = Female, 1 = Male
)

# Run pre-training bias analysis
clarify_processor = clarify.SageMakerClarifyProcessor(...)
clarify_processor.run_pre_training_bias(
    data_config=data_config,
    bias_config=bias_config
)
```

**Findings:**

| Metric | Value | Interpretation |
|--------|-------|----------------|
| **Class Imbalance (CI)** | 0.35 | 65% approved, 35% denied - moderate imbalance |
| **Facet Imbalance (FI)** | 1.45 | Male applicants are 45% more likely to be in the "approved" class |
| **Facet Correlation** | 0.28 | Moderate positive correlation between being male and approval |

**Interpretation:**
- The training data shows gender imbalance, with male applicants overrepresented in approved loans.
- This could lead the model to learn biased patterns that favor male applicants.

**Mitigation Actions:**
1. Apply class weighting to balance approved/denied classes.
2. Use resampling techniques to balance gender representation across approval outcomes.
3. Consider removing gender as a feature if not legally required.

### Step 3: Post-Training Bias Detection

**Objective:** Evaluate bias in the trained model's predictions.

```python
# Configure model
model_config = ModelConfig(
    model_name='loan-approval-model',
    instance_type='ml.m5.xlarge',
    instance_count=1,
    accept_type='text/csv'
)

# Run post-training bias analysis
clarify_processor.run_post_training_bias(
    data_config=data_config,
    bias_config=bias_config,
    model_config=model_config,
    model_predicted_label_config=ModelPredictedLabelConfig()
)
```

**Findings:**

| Metric | Value | Interpretation |
|--------|-------|----------------|
| **Differential Validity (DV)** | Precision: 0.88 (Male) vs. 0.82 (Female) | Model is 6% more precise for male applicants |
| **Differential Prediction Bias (DPB)** | 0.12 | Model predicts approval 12% more often for male applicants with identical features |
| **Disparate Impact (DI)** | 0.78 | Female approval rate is 78% of male approval rate (threshold: 0.80) |

**Interpretation:**
- The model exhibits bias, favoring male applicants even after data balancing.
- Disparate Impact below 0.80 indicates potential regulatory concerns.

**Mitigation Actions:**
1. Apply fairness constraints during training (e.g., equalized odds).
2. Post-process predictions to equalize approval rates across genders.
3. Retrain with adversarial debiasing techniques.

### Step 5: Production Monitoring with Data Drift Detection

**Objective:** Monitor for data drift and bias drift in production.

```python
from sagemaker.model_monitor import DataCaptureConfig, ModelMonitor

# Enable data capture
data_capture_config = DataCaptureConfig(
    enable_capture=True,
    sampling_percentage=100,
    destination_s3_uri='s3://bucket/data_capture'
)

# Deploy model with monitoring
predictor = estimator.deploy(
    initial_instance_count=1,
    instance_type='ml.m5.xlarge',
    data_capture_config=data_capture_config
)

# Schedule monitoring job
monitor = ModelMonitor(...)
monitor.create_monitoring_schedule(
    monitor_schedule_name='loan-model-monitor',
    endpoint_input=predictor.endpoint_name,
    statistics=baseline_statistics,
    constraints=baseline_constraints
)
```

**Monitoring Results (After 30 Days):**

| Metric | Training | Production | Drift Detected? |
|--------|----------|------------|-----------------|
| Average Income | $52,000 | $48,000 | Yes (7.7% decrease) |
| Average Credit Score | 680 | 665 | Yes (2.2% decrease) |
| Gender Distribution | 52% Male | 58% Male | Yes (6% shift) |
| Approval Rate (Female) | 62% | 55% | Yes (7% decrease) |

**Interpretation:**
- Production data shows lower average income and credit scores, indicating a shift in applicant demographics.
- Gender distribution has shifted toward more male applicants.
- Female approval rate has decreased, suggesting potential bias drift.

**Mitigation Actions:**
1. Retrain the model with recent production data to adapt to demographic shifts.
2. Investigate the cause of the approval rate decrease for female applicants.
3. Apply bias mitigation techniques if disparate impact persists.

## 5. Best Practices

- **Enable Clarify Early:** Run bias detection on training data before investing in model training.
- **Monitor Multiple Facets:** Evaluate bias across all sensitive attributes (gender, age, race, etc.).
- **Combine Metrics:** Use multiple bias metrics to get a comprehensive view of fairness.
- **Integrate Explainability:** Always provide explanations for high-stakes decisions (loans, hiring, healthcare).
- **Continuous Monitoring:** Use Model Monitor to detect drift and bias drift in production.
- **Document Everything:** Maintain audit trails of bias detection, mitigation actions, and compliance reports.
- **Iterate and Improve:** Bias mitigation is an iterative process—continuously refine models based on Clarify insights.
