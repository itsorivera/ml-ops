# Model Evaluation Techniques and Metrics

## 1. Purpose of Model Evaluation
Model evaluation determines if a trained model is ready for production by assessing its predictive performance on unseen data. Proper evaluation ensures the model generalizes well and meets business objectives.

## 2. Dataset Splitting: Validation vs. Test Sets
- **Training Set**: Used to fit the model (typically 80%).
- **Validation Set**: Used for tuning and iterative improvement (commonly 10%).
![Dataset Splitting](/assets/ValidationSet.png)
- **Test Set**: Used for final evaluation of predictive quality (commonly 10%).
![Dataset Splitting](/assets/EvaluationSet.png)



Validation identifies areas for model improvement. Testing provides an unbiased estimate of real-world performance.

## 3. Classification Metrics

- **Confusion Matrix**: The confusion matrix is a tabular summary of predictions versus actual class labels for a classification problem. It provides counts for:
    - **True Positive (TP):** Correctly predicted positive class
    - **True Negative (TN):** Correctly predicted negative class
    - **False Positive (FP):** Incorrectly predicted positive class (Type I error)
    - **False Negative (FN):** Incorrectly predicted negative class (Type II error)
![Confusion Matrix](/assets/MatrixCount.png)
    - **Strengths:** Enables calculation of all core classification metrics. Provides granular insight into model errors.
    - **Weaknesses:** Can become complex for multiclass problems.
    - **Context:** Essential for understanding the types of errors and for calculating precision, recall, etc.

- **Accuracy**: The proportion of total correct predictions. 
    - **Formula:** `(TP + TN) / (TP + TN + FP + FN)`
![Accuracy Matrix](/assets/Accuracymatrix.png)
    - **Interpretation:** Fraction of predictions the model got right.
    - **Strengths:** Simple, intuitive, widely reported.
    - **Weaknesses:** Misleading for imbalanced datasets (e.g., rare positive class).
    - **Context:** Use only when classes are balanced and all errors have similar cost.

- **Precision**: The proportion of positive predictions that are actually correct.
    - **Formula:** `TP / (TP + FP)`
![Precision Matrix](/assets/Precisionmatrix.png)
    - **Interpretation:** Of all predicted positives, how many are truly positive?
    - **Strengths:** Useful when the cost of false positives is high (e.g., spam detection, medical screening).
    - **Weaknesses:** Ignores false negatives; can be misleading if recall is low.
    - **Context:** Prioritize when false positives are more costly than false negatives.

- **Recall (Sensitivity, True Positive Rate):** The proportion of actual positives that are correctly identified.
    - **Formula:** `TP / (TP + FN)`
![Recall Matrix](/assets/Recallmatrix.png)
    - **Interpretation:** Of all actual positives, how many did the model detect?
    - **Strengths:** Critical when missing positives is costly (e.g., disease detection, fraud detection).
    - **Weaknesses:** Ignores false positives; can be misleading if precision is low.
    - **Context:** Prioritize when false negatives are more costly than false positives.

- **F1 Score**: The harmonic mean of precision and recall, balancing both concerns.
    - **Formula:** `2 * (Precision * Recall) / (Precision + Recall)`
    - **Interpretation:** Single metric balancing precision and recall; high only if both are high.
    - **Strengths:** Useful for imbalanced classes and when both false positives and false negatives matter.
    - **Weaknesses:** Does not distinguish between types of errors; may obscure underlying issues.
    - **Context:** Standard for comparing classifiers on imbalanced datasets.

- **AUC-ROC**: Area Under the Receiver Operating Characteristic Curve.
    - **Definition:** Plots True Positive Rate (Recall) vs. False Positive Rate (FP / (FP + TN)) at various thresholds.
![AUC-ROC](/assets/AUCROC.png)
    - **Interpretation:** Probability that the classifier ranks a random positive higher than a random negative. Ranges from 0.5 (random) to 1 (perfect).
    - **Strengths:** Threshold-independent; robust to class imbalance; useful for model selection.
    - **Weaknesses:** Can be misleading in highly skewed datasets; does not reflect real-world cost ratios.
    - **Context:** Use for ranking models and selecting optimal thresholds.

Example: Email spam classification

![Email Spam Classification](/assets/EmailExampleAUCROC.png)

In email spam classification, emails are ranked by risk score. The ROC curve illustrates the trade-off between capturing spam (TPR) and misclassifying good emails (FPR). The 'knee' of the curve is often the optimal threshold for deployment.

- **Heatmaps**: Visual representation of confusion matrices, especially for multiclass problems.
![Heatmap](/assets/Heatmap.png)
    - **Strengths:** Quickly highlights strengths and weaknesses across all classes.
    - **Weaknesses:** Can become visually cluttered with many classes.
    - **Context:** Best for multiclass evaluation and communicating results to stakeholders.

## 4. Regression Metrics

- **Mean Squared Error (MSE)**: Average of squared differences between predicted and actual values.
![MSE](/assets/MSEGraph.png)
    - Lower is better. Sensitive to outliers.

- **Root Mean Squared Error (RMSE)**: Square root of MSE.
    - Same units as target variable. Easier to interpret.

- **R-squared (`R²`)**: Fraction of variance explained by the model.
    - Ranges from 0 to 1. Higher means better fit, but can increase with more variables (risk of overfitting).

- **Adjusted R-squared**: Penalizes model complexity. Only increases if new variables improve the model more than expected by chance.
    - Preferred for multiple regression.

## 5. Metric Selection Guidance
- Choose metrics aligned with the business objective and data characteristics.
- For imbalanced classification, prefer precision, recall, F1, or AUC-ROC over accuracy.
- For regression, use both `R²` and adjusted `R²` to monitor overfitting.
- Always validate on held-out data and report multiple metrics for a comprehensive evaluation.
